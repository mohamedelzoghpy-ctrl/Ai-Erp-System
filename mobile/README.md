# MOZAD Mobile — تطبيق المندوبين (Expo / React Native)

تطبيق الميدان لـ MOZAD ERP: **أوفلاين أولاً** — الأصناف والعملاء محلية (SQLite)،
الأوردرات تُحفظ محلياً بمعرف فريد (`client_ref`) وتُرفع idempotent مع المزامنة،
والإشعارات تُدفع عبر FCM (P0).

## الشاشات
| الشاشة | الوصف |
|---|---|
| الرئيسية | ملخص اليوم + زر المزامنة + عدد المعلق |
| الأصناف | كتالوج محلي ببحث — يضيف للسلة بسعر قائمة العميل |
| العملاء | أرصدة وحدود ائتمان — اختيار عميل يضبط قائمة أسعاره |
| أوردر جديد | السلة → حفظ أوفلاين (لا يحتاج شبكة) |
| أوردراتي | المعلق + المرفوع |
| الإشعارات | صندوق المندوب (تأكيد/تحصيل/مرتجع) |
| الوردية | فتح/إقفال برصيد افتتاحي وعدّ فعلي |
| لوحة المدير | KPIs من تقارير النظام (لصلاحيات المدراء) |

## التشغيل أول مرة (على جهازك)
```bash
cd mobile
npm install
npx expo start        # ثم افتح Expo Go على الأندرويد وامسح الـQR
```

### ضبط عنوان الـAPI
في `app.json` → `extra.apiBaseUrl`:
- محاكي أندرويد: `http://10.0.2.2:8000` (الافتراضي)
- جهاز حقيقي على نفس الشبكة: `http://<IP جهازك>:8000`
- عبر النفق العام: `https://small-cucumber-paprika.ngrok-free.dev`

## كيف تعمل المزامنة
1. **سحب**: `GET /sync/bootstrap?since=<last_sync>` — دلتا للمنتجات/العملاء + قوائم أسعار كاملة → SQLite
2. **دفع**: الأوردرات في `pending_orders` تُرفع دفعة واحدة `POST /sync/orders` —
   كل أوردر بـ`client_ref` فريد؛ إعادة المحاولة تعيد نفس الأوردر (**لا تكرار أبداً**)،
   وفشل عنصر لا يُسقط الدفعة — يبقى محلياً بآخر خطأ للمحاولة القادمة.
3. الجلسات: `POST /auth/refresh` تلقائي عند 401 (توكنات في SecureStore).

## ربط حساب مندوب
من واجهة الويب: المندوبون ← **ربط مستخدم** (يُنشئ حساباً بكلمة سر لمرة واحدة) —
ثم سجّل الدخول بالتطبيق. لتسجيل جهاز الإشعارات: يُسجل تلقائياً عند أول تشغيل
(أضف `expo-device` + استدعاء `POST /reps/me/devices` — موضع جاهز في api.ts).
